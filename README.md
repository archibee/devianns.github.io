# Dahlia 커뮤니티 아카이브

SOOP, YouTube 등 여러 플랫폼에서 활동한 기록을 한곳에 모아 열람할 수 있는 개인 커뮤니티 아카이브입니다. 플랫폼에 게시된 동영상, 캐치, 클립을 이 사이트에 복사하거나 업로드하지 않습니다. 기록에는 제목, 플랫폼, 날짜, 분류 등의 메타데이터를 저장하며, 수집 시점에 확인한 개별 원본 링크가 있으면 함께 제공합니다.

## 방향

- GitHub Pages에 올릴 수 있는 정적 웹사이트로 만듭니다. 별도의 GitHub Actions 배포 로직, 서버, 동적 데이터베이스에 의존하지 않습니다. 아카이브의 `database/`는 정적 기록 파일을 담는 폴더입니다.
- PC, 태블릿, 모바일 화면에 대응하는 반응형 메인 화면과 아카이브 열람 경험을 제공합니다.
- 메인 큐브 앞면에는 `dahlia-images/dahlia.jpg`, 뒷면에는 `dahlia-images/dahlia-background.jpg`를 한 면씩 사용합니다. 나머지 은하 배경은 CSS 별빛과 색감으로 구성합니다.
- 아카이브 항목은 링크와 메타데이터를 기반으로 표시하며, 방문자가 원본 플랫폼에서 콘텐츠를 보도록 안내합니다.

## 현재 아카이브 화면

메인 화면의 유리 큐브는 SOOP, YouTube, X, Community, Projects, 프로필 링크의 여섯 면을 각각 전용 정적 페이지에 연결합니다. SOOP 페이지는 캐치와 클립/VOD를 함께 보여줍니다. Community는 카페별 게시글 기록을 날짜·작성자·목록 수치로 살펴보며, 현재 데이터는 VLUP 카페 한 곳에서 모았습니다. Projects 페이지는 프로젝트 JSON을 읽어 소개와 관련 링크를 렌더링하며, 픽셀 도구와 함께 VLUP 팬게임 두 편을 별도 프로젝트로 소개합니다. 팬게임 카드에는 공식 카페 배포 안내와 가이드라인을 항상 가까이 표시하고, 게임 실행은 VLUP 카페 게시글을 통해 확인하도록 안내합니다. 모든 페이지의 상단바는 배경색·블러·테두리·그림자 없이 완전히 투명하게 표시합니다.

| 화면 | 내용 |
| --- | --- |
| 메인 큐브 | 드래그·스와이프·방향키로 SOOP, YouTube, X, Community, Projects, 프로필 링크 면을 둘러봅니다. |
| SOOP | 캐치·클립·VOD 기록, 유형 필터, 캐치 월별·요일별·시간대별 흐름, 검색 |
| Projects | 프로젝트 JSON 소개 카드. VLUP 팬게임 두 편은 원문 소개글과 GitHub 저장소, 공식 배포 지침을 함께 안내 |
| YouTube | Shorts/동영상 분포, 기록된 조회수 상위 항목, 태그와 형식 필터 |
| X | 확인된 게시물의 월별 흐름, 태그와 본문 검색 |
| Community | 카페별 게시글의 월별·작성자별 수, 수집 당시 목록 조회 수, 제목·본문 검색. 카드에서 원문 링크와 저장된 본문 열기를 각각 선택할 수 있습니다. 현재 등록된 카페는 VLUP입니다. |
| 원본 계정 | SOOP, YouTube, X 계정 링크 |

각 화면은 [현재 사이트 구성 문서](docs/site-architecture.md)에 자세히 설명되어 있습니다.

검색과 링크 공유에 필요한 페이지별 제목·설명, canonical 주소, Open Graph/Twitter 미리보기, 사이트 아이콘과 공개 화면 사이트맵을 정적 HTML/XML 파일에 설정합니다. 자세한 기준과 현재 상태는 [사이트 구성 문서](docs/site-architecture.md)의 검색 메타데이터 항목을 참고하세요.

정적 카탈로그에는 활동 기록 1,997개가 있습니다. SOOP 캐치 1,696개(수기 발췌와 ID 기반 목록 포함), SOOP 클립 43개, SOOP 일반 VOD 7개, YouTube Shorts 45개와 동영상 15개, X 게시물 14개, Naver Cafe 글 기록 177개입니다. Community 화면은 카페 선택을 지원하며 현재 등록된 데이터는 VLUP 한 곳뿐입니다. 공개 열람이 확인된 게시물은 본문 텍스트와 본문에 포함된 링크 주소를 함께 저장합니다. 카드에서 카페 원문으로 이동하거나 저장된 텍스트를 사이트 안에서 볼 수 있으며, 이미지·영상 파일은 복제하지 않습니다. 기록 숫자는 저장된 메타데이터 조각 수이며, 같은 제목이나 별도 수집 배치가 같은 활동일 가능성이 있을 때 임의로 합치지 않습니다. 원본 수집의 범위와 한계는 `docs/imports/`의 플랫폼별 수집 기록을 참고하세요.

브라우저는 활동 JSON 원본을 직접 열거하지 않고 정적 `database/catalog.json`을 읽어 검색·필터·시각화를 제공합니다. 개별 JSON은 원본 기록으로 남고, 카탈로그는 화면에 필요한 필드의 정적 색인입니다. 파일을 추가하거나 변경하면 카탈로그도 같이 갱신합니다. Actions, 서버, 브라우저 저장 기능은 사용하지 않습니다.

## 아카이브 기록과 콘텐츠 입력

`database/` 폴더 아래에 기록 파일을 쌓아가는 파일 기반 아카이브로 운영합니다. 기록 파일 하나는 실제 영상이나 게시물을 담는 파일이 아니라, 실제 활동의 흔적을 가리키는 메모리 조각 하나입니다. 수집 자료에 개별 활동을 직접 가리키는 원본 링크가 있거나 수집 시점에 해당 항목에서 링크를 확인할 수 있었다면, 그 링크를 기록에 보존하는 것을 최소 기준으로 삼습니다. 계정이나 목록 페이지 링크로 개별 활동 링크를 대신하지 않습니다. 개별 링크를 확인할 수 없었던 자료는 제목으로 주소를 추측해 만들지 않고, 링크가 없다는 점을 남긴 메타데이터 기록으로만 보존합니다. 파일과 폴더 경로로 기록을 목적별 또는 플랫폼별로 구분할 수 있게 합니다.

사용자가 나중에 제공하는 링크와 메타데이터를 기록 단위로 정리해 내부 데이터 파일로 추가합니다. 구체적인 파일 형식과 분류 체계는 실제 자료가 모이면서 정합니다. 사이트는 이 파일들을 정적으로 읽어 표시하며, 사이트 화면에서 저장소나 데이터 파일을 직접 수정하지 않습니다. 원본 플랫폼 링크는 해당 플랫폼으로 이동하는 링크이고, 사이트 안에서 영상이나 캐치, 클립을 실행하거나 호스팅하지 않습니다.

사용자는 플랫폼에서 복사한 원시 자료를 자유로운 형식으로 제공할 수 있습니다. 자료를 주기 전에 스키마에 맞춰 직접 가공할 필요는 없습니다. 자료가 들어오면 계정 스냅샷과 개별 활동을 구분하고, 날짜/상대 시각, 제목/본문, 링크, 이름이 확인된 수치, 반복 주제와 이벤트 후보를 분석해 축적합니다. 확인되지 않은 URL, 지표의 의미, 중복 여부, 절대 날짜는 추측으로 보충하지 않습니다. 누적 분석과 미확정 패턴은 `docs/social-scrape-observations.md`에 정리하고, 실제 개별 데이터 파일의 구조와 웹사이트 활용 방식은 자료가 충분히 모인 뒤 정합니다.

정적 호스팅은 폴더 안의 파일을 자동 열거할 수 없으므로, 화면에 표시할 기록 파일을 나열하는 정적 색인(manifest) 파일이 필요합니다. 색인과 기록 파일 모두 저장소에 일반 파일로 커밋해 관리하며, 별도 서버나 Actions 배포 절차를 요구하지 않습니다. 추후 필요해지면 기록 파일 추가 후 메타데이터를 정리하고 색인 등 표시용 정적 파일을 갱신하는 로컬 스크립트를 둘 수 있습니다. 이는 향후 확장 방향이며 현재 우선순위는 사이트의 시각적 완성도와 기본 프로젝트 구조입니다.

## 시각적 방향

기록을 편리하게 찾는 기능과 함께, 아카이브 자체를 세련되고 시각적으로 매력 있게 구성합니다. 첫 화면 한가운데 크게 놓인 투명하고 부드러운 유리 큐브를 핵심 비주얼이자 탐색 오브젝트로 사용합니다. 첫 진입은 큐브 윗면이 살짝 보이는 내려다보는 각도로 시작합니다. CSS 3D 면 회전, 투명한 그라데이션과 정적인 반사 하이라이트로 유리 느낌을 유지합니다. 마우스/터치 드래그와 키보드 방향키로 가로·세로 두 축을 돌리고, 손을 놓으면 관성으로 감속합니다. 여섯 면은 SOOP, YouTube, X, Community, Projects, 프로필 링크로 이동합니다. 모든 페이지의 상단바는 배경색, 블러, 테두리, 그림자 없이 완전히 투명하게 유지하고 메인과 상세 페이지에서 크기와 간격을 통일합니다. 큐브 면에 backdrop blur를 적용하거나 장식의 무한 애니메이션을 실행하지 않아 첫 화면 렌더링을 가볍게 유지합니다. 프로필 및 배너 이미지는 큐브와 배경에 어울리도록 통합합니다. 페이지는 앱처럼 의도한 컨트롤과 링크 중심으로 동작하도록 텍스트 선택과 네이티브 이미지 드래그를 막습니다.

## 저장소 구조

- `index.html`: 메인 페이지
- `memories.html`, `youtube.html`, `x-archive.html`: 플랫폼별 기록 페이지
- `community.html`: VLUP 카페 게시글 커뮤니티 기록과 시각화
- `projects.html`, `projects-app.js`: 프로젝트 소개 페이지와 JSON 렌더러
- `database/projects/`: 프로젝트 소개 JSON과 정적 목록
- `database/projects/guidelines/vlup-fangame-guideline.json`: 두 팬게임 카드에 연결되는 공식 카페 배포 지침 요약과 원문 링크
- `platforms.html`: 원본 플랫폼 계정 링크 페이지
- `styles.css`: 반응형 레이아웃과 별빛/유리 질감 스타일
- `subpages.css`: 하위 페이지 공통 스타일
- `script.js`: 모바일 내비게이션 등 작은 인터랙션
- `archive-app.js`: 정적 카탈로그를 읽는 검색·필터·카드·차트 렌더러
- `.nojekyll`: GitHub Pages에서 Jekyll 처리 없이 정적 파일을 제공하기 위한 표시 파일
- `favicon.svg`, `favicon.ico`, `favicon-32.png`, `apple-touch-icon.png`: 브라우저와 모바일 홈 화면 아이콘
- `icon-192.png`, `icon-512.png`, `site.webmanifest`: 사이트 이름, 색상, 앱 아이콘 설정
- `robots.txt`, `sitemap.xml`: 검색 로봇 접근 안내와 공개 페이지 목록
- `404.html`: 찾을 수 없는 주소를 위한 안내 페이지
- `dahlia-images/`: 프로필 및 배경 이미지
- `database/`: 플랫폼별 SNS 프로필과 활동 기록 텍스트/메타데이터 파일
- `database/catalog.json`: GitHub Pages에서 바로 읽는 화면용 정적 카탈로그
- `database/README.md`: 활동 데이터 경로와 필드 처리 규칙
- `docs/imports/source-1-summary.md`: 첫 대량 자료의 축적 결과와 관찰 패턴
- `docs/site-architecture.md`: 현재 페이지, 코드, 데이터 흐름, SEO 및 동작 설명
- `source/`: 원시 스크랩 입력용 로컬 폴더. Git에서 제외하며 정적 사이트에 배포하지 않음
- `database/platforms/`: 사용자가 제공한 SNS 계정 링크 메타데이터
- `database/naver-cafe/vlup/posts/`: 공개 작성자 검색에서 축적한 Naver Cafe 게시물 메타데이터. 공개 본문 텍스트와 링크 참조를 저장하며 Community 화면에서 원문/저장 기록을 함께 제공
- `database/platforms/naver-cafe-vlup.json`: VLUP 카페 ID와 사용자가 확인한 Dahlia 닉네임 별칭, 수집 검색 경로
- `docs/social-scrape-observations.md`: 사용자가 제공한 SNS 화면 자료에서 추출한 패턴과 데이터 정리 주의점
- `docs/imports/naver-cafe-vlup-2026-11-01.md`: VLUP 카페 공개 작성자 검색의 수집 범위와 한계
- `README.md`: 사이트 목적과 콘텐츠 운영 개요
- `AGENTS.md`: 이후 구현 작업을 위한 개발 및 운영 지침

## 기록 화면의 시각화

기록 화면은 데이터 카드와 함께 플랫폼 비중, 게시 시기, 요일·시간대, 영상 형식, Community의 닉네임별 게시 수와 수집 당시 조회 수 순위처럼 실제 메타데이터로 확인할 수 있는 흐름을 유리 패널 안의 막대 차트와 순위 표시로 보여줍니다. 날짜나 수치가 제공되지 않은 항목은 시각화에 임의로 채우지 않으며, 기록에 있는 값만 집계합니다.
