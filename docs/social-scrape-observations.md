# SNS 스크랩 자료 관찰 메모

이 문서는 사용자가 제공한 X, YouTube, SOOP 화면 텍스트를 읽고 확인 가능한 계정 정보와 활동 패턴을 누적하는 분석 메모다. 사용자는 원시 복사/스크랩 자료를 자유로운 형식으로 전달하며, 사전 정리나 스키마는 요구하지 않는다. 개별 게시물/동영상/캐치의 실제 링크와 첫 자료의 스크랩 시각은 제공되지 않았다. 따라서 이 메모는 개별 활동 데이터베이스 레코드가 아니며, 화면에 보인 항목을 임의로 게시물로 확정하거나 링크를 만들어내지 않는다. 앞으로 새 자료가 올 때마다 관찰과 패턴 후보를 추가하되, 확인된 사실과 추론을 분리한다.

## 활동 단위 패턴

### X 게시물

- 화면 발췌에는 게시물 5행이 보인다. 네 행은 `2025-07-12`, 한 행은 `2025-06-28`로 날짜가 명시되어 있다.
- `#iana_live #jooin_on #sitry_on #beldir_live` 문구가 같은 날짜로 두 번 보인다. 게시물 URL/ID가 없으므로 실제 중복 게시물인지 화면 추출 중복인지 판별할 수 없다. 우선 두 행을 보존하고, 링크가 제공된 뒤 중복 여부를 확인한다.
- 나머지 발췌 문구는 `#Jooin_on 선물🎁`, `#Jooin_on 🌱`, `#Jooin_on 👊주인펀치💥`다. `#Jooin_on`이 반복되며 `#iana_live`, `#sitry_on`, `#beldir_live`도 등장한다.
- 날짜와 본문은 확인되지만 개별 게시물 URL, 시각, 재게시/답글 관계는 없다.

### YouTube 동영상 목록

- 프로필은 동영상 60개라고 표시하지만, 붙여넣은 제목/조회수 목록은 일부 발췌이므로 채널 전체 목록으로 간주하지 않는다.
- 제목에는 `#이주인`, `#vtuber`와 크리에이터 이름/팬 태그가 반복된다. 가상 크리에이터 팬 클립, 표정·애교·대화 리액션, 밈/짧은 상황극, 일상·취미, ASMR이 눈에 띄는 주제 묶음이다. 이는 제목에서 얻은 검색용 주제 태그 후보이지, 제작 의도나 실제 내용에 대한 확정 분류는 아니다.
- 제목 표현은 짧은 감탄/리액션형(예: `냥냥펀치!`, `엣치`)과 질문/대화형(예: `뭐라고했어~? 안들려`, `점메추 컴온`, `저랑 순애요?`)이 반복된다. 향후 제목 검색/분류에서 `reaction`, `question`, `meme`, `ASMR` 같은 태그 후보를 만들 수 있다.
- 제공된 발췌에는 각 항목의 제목과 `조회수`가 함께 표시되어 있다. 값은 `1.3천회`, `2.4천회`처럼 축약되어 있으므로 원문 표시를 보존하고, 숫자로 변환할 때는 근삿값임을 표시한다.
- 이 발췌에서 보이는 조회수 범위는 `25회`부터 `2.4천회`까지다. 이는 붙여넣은 일부 항목의 스냅샷일 뿐이고, 영상별 게시일이 없어 시간에 따른 성과 추세는 계산할 수 없다.
- 동영상별 게시일, 영상 URL/ID, 현재 선택된 정렬 방식은 확인되지 않는다. 화면에 `최신순`, `인기순`, `날짜순` 탭이 보인다는 사실만으로 목록의 정렬 상태를 추정하지 않는다.

### SOOP 캐치

- 캐치 수는 1,803개로 표시된다.
- 제공된 상단 목록에는 `1시간 전`, `2일 전` 같은 상대 시각과 `2026-10-24` 같은 명시 날짜가 섞여 있다. 상대 시각을 절대 날짜로 바꾸려면 실제 스크랩 시각이 필요하다. 자료에서 그 시각을 확인할 수 없으므로 원문 그대로 보관한다.
- 제목에서는 운동/도전, 할로윈 의상·강시 콘셉트, J-pop 노래대회, 방송 중 장난·대화, 뷰티/매니큐어 등의 주제가 보인다. `운동 업보 청산의 날...` 등 같은 제목이 반복되며 뒤의 숫자가 다른 행도 있다. URL 또는 캐치 ID가 없으면 서로 다른 콘텐츠인지, 반복 노출인지 단정하지 않고 행마다 보존한다.
- 같은 명시 날짜인 `2026-10-24` 아래 할로윈/강시 관련 항목과 J-pop 노래대회 항목이 모여 있어 날짜별 방송/이벤트 묶음을 구성할 수 있다. 운동 관련 캐치도 제목이 다른 여러 조각으로 이어져 있어 하나의 방송 회차 아래 하위 클립으로 묶을 가능성이 있다. 단, 회차 식별자/방송 링크가 없으므로 이 연결은 후보로만 둔다.
- 각 캐치 제목 뒤의 작은 정수(예: `2`, `17`, `50`)가 보이지만, 붙여넣은 화면에는 그 수치의 라벨이 남아 있지 않다. 조회수나 좋아요 수로 이름 붙이지 말고 원시 표시값과 `metricType: unknown`으로 다룬다.
- 목록에 `최신순`, `인기순`, `날짜순` 선택지가 있지만 어떤 정렬이 적용됐는지는 명시되지 않았다.

## 텍스트 정리 시 보존할 것

스크린샷/복사 텍스트를 데이터로 바꿀 때 다음 항목을 서로 구분한다.

- 계정 프로필 정보와 개별 활동(게시물, 동영상, 캐치)
- 콘텐츠 제목/본문과 UI 문구(탭, 버튼, 구독 상태, `...더보기`)
- 명시 날짜와 원문 상대 시각(`2일 전` 등)
- 이름이 확인된 지표(YouTube 조회수)와 라벨이 불확실한 숫자(SOOP 캐치 숫자)
- 실제 반복 콘텐츠와 추출 과정에서 중복됐을 가능성이 있는 행
- 원문 표시값과 정규화/분류를 통해 새로 만든 값

원시 제목과 상대 날짜 표시를 남겨두면 이후 분류나 파싱 규칙을 바꾸더라도 원본을 다시 검토할 수 있다. URL이나 플랫폼 ID가 없으면 누락 상태로 남기고 추측해 채우지 않는다.

## 향후 레코드 필드 제안

아래는 현재 확정 스키마가 아니라 이후 JSON 한 파일당 활동 하나를 저장할 때 사용할 후보 필드다.

| 필드 | 용도 |
| --- | --- |
| `platform` | `x`, `youtube`, `soop` |
| `contentType` | `post`, `video`, `catch` 등 |
| `title` / `text` | 화면에서 확인한 제목 또는 게시물 본문 |
| `url` / `platformId` | 실제 원본 링크나 플랫폼 ID. 확보된 경우에만 입력 |
| `publishedAt` | 확정 가능한 ISO 날짜/시각. 정밀도가 날짜뿐이면 시각을 만들지 않음 |
| `publishedLabelRaw` | 화면의 원래 날짜/시간 표현, 예: `2일 전` |
| `observedAt` | 프로필/조회수처럼 변하는 값을 읽은 시각 |
| `metrics` | 이름과 값이 확인된 조회수·팔로워 등. 원시 표시값도 보존 |
| `tags` | 해시태그/주제 분류. 원문 해시태그와 분석 태그를 구분 |
| `sourceOrder` / `rawExcerpt` | 붙여넣은 발췌에서의 순서와 검토용 원문 |

현재 데이터 분류 및 경로는 자료에 따라 확장한다. 현재는 `database/x/posts/`, `database/youtube/videos/`, `database/soop/catches/`로 플랫폼과 콘텐츠 종류를 나누고, 각 활동을 별도 JSON 파일로 저장한다.
